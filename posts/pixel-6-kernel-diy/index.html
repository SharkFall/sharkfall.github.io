前情提要
#

关键词: Arm64 Mac 编译 Pixel 6 内核及内核模块、rwProcMem33、eBPF 环境, 一文梭哈完整链路

写这篇 blog 的时候遇到了不少问题，从头开始完整走通了一遍，把这些踩坑经验全整合在这儿，希望能帮到屏幕前的你。

我的设备是:

  • Pixel 6 Android 14 (AP2A.240905.003.F1, Sep 2024) -> 镜像下载
  • Mac Pro M5 Max

0x0: 最重要的一步
#

区分大小写的磁盘映像
#

这里是第一个坑

Danger
  • 这一步跳过的话，后面你会被各种诡异报错折磨到怀疑人生。
  • 不要问我怎么知道的，我 ++

Mac 的文件系统默认对大小写不敏感，而这对于 Linux 内核编译是致命的。你会遇到：

  • Documentation/Kbuild: Is a directory. — 因为大小写不敏感，Kbuild 和 kbuild 被认成同一个东西
  • No rule to make target 'net/netfilter/xt_DSCP.o' — xt_DSCP.c 和 xt_dscp.c 傻傻分不清
  • 以及其他各种"明明文件在那儿你就是找不到"的玄学 bug

解决方法：创建一个区分大小写的磁盘映像，所有工作全部放在这个映像里。

打开 磁盘工具（Disk Utility）：

  1. 菜单栏 文件 > 新建映像 > 空白映像
  2. 关键参数：
    • 名称：CompileTask（随便）
    • 大小：至少 30GB，建议 40-50GB（源码 + 编译产物很大）
    • 格式：APFS（区分大小写） 或 APFS（区分大小写，加密）
  3. 创建后挂载，你会得到一个 /Volumes/CompileTask/ 路径

创建好之后，在里头建好工作目录：

mkdir -p /Volumes/CompileTask/docker/workplace

后面的所有操作，工作目录都指向这个区分大小写的磁盘映像，把它当成你的专属 Linux 开发盘。

0x1: Docker 部署 Ubuntu
#

这里是第二个坑

Google 已经停止维护 Mac 上的工具链，只能自己编译或寻找公开可用的。

在用 Docker 之前也挣扎过，想直接在 Mac 本机编译，奈何没有找到合适的 arm64 交叉编译器，放弃 ~~~

也尝试过 VMWare 运行 arm64 Ubuntu 22.04，问题并没有解决，仍然没有合适的 arm64 linux 交叉编译器。

最后 Docker 部署运行 amd64 ubuntu 22.04 完美成功，没想到性能损失微乎其微，感谢 Docker，感谢开源！

下载并启动镜像
#

部署 Docker 非常傻瓜式，安装 Docker Desktop 并启动，再打开 shell：

docker run -it \
    --name ubuntu \
    --platform linux/amd64 \
    -u root \
    --restart always \
    -v /Volumes/CompileTask/docker/workplace:/workplace \
    ubuntu:22.04
  • --name ubuntu：推荐设置，后面操作方便
  • --platform linux/amd64：一定要设置，工具链是适用 amd64 架构的
  • -v /Volumes/CompileTask/docker/workplace:/workplace：映射我们刚才在区分大小写磁盘映像中建的目录

启动容器并打开 shell：

docker start ubuntu
docker exec -it ubuntu bash

不用了可以关掉：

docker stop ubuntu

0x4: 下载内核源码
#

Tip

这一段建议先看完，不要着急复现

正确的做法是用 Repo 下载完整源码后在本地查, 上面只是为了确认分支

下载 Repo 工具
# 

curl https://storage.googleapis.com/git-repo-downloads/repo > /usr/local/bin/repo
chmod +x /usr/local/bin/repo

有魔法直接继续，没有的话可以用清华镜像。

下载源码
#

Danger

注意一点：先进入你要下载的 AOSP manifest 仓库看看 default.xml， 重点关注 <project path="build" name="kernel/build"，如果 revision 的值为 main， 请千万不要下载，否则你会发现下载下来之后根本无法 build！ 这是由于 build 仓库和内核源码仓库不同步导致的。

  • 引用自 Arm64 Mac DIY Pixel 6 内核踩坑笔记 - 0x1

分支是 android-gs-raviole-5.10-android14-qpr3（上一节确认过的）：

mkdir pixel-6-a14-5.10-j32 && cd pixel-6-a14-5.10-j32/
repo init -u https://android.googlesource.com/kernel/manifest -b android-gs-raviole-5.10-android14-qpr3
repo sync -j32

使用 Repo 工具会下载包括交叉编译工具链在内的所有依赖，需要等一会儿。

切换到目标 commit
#

repo sync 下来的代码默认在最新状态，需要切到我们设备对应的 commit：

cd private/gs-google
git checkout android-gs-raviole-5.10-android14-qpr3
git reset --hard 12f3388846c3
Danger

一定要先 git checkout 分支，再 git reset --hard 到目标 commit。 否则 repo sync 可能导致代码处于 detached HEAD 状态，部分文件被意外修改， 编译时会报一堆 incomplete definition of type 错误。

0x5: 编译内核
#

Skip ramdisk ?
#

看到别的大佬们的分享都是有解包 ramdisk 这一步的, 在 google source 也有提到

但是我的手机的 boot.img 解包出来只有kernnel , ramdisk 是在 vendor_boot.img 中, 所以这里 skip 了

如果有的话可以参考 解包 boot.img

创建内核配置 fragment
#

单独写一份内核配置，只写我们需要的（支持 kprobes、eBPF 等）：

cat > private/gs-google/arch/arm64/configs/shark.fragment << 'EOF'
# hardware break point and kprobe
CONFIG_IKHEADERS=y
CONFIG_HAVE_KPROBES=y
CONFIG_KPROBES=y
CONFIG_KPROBE_EVENTS=y
CONFIG_HAVE_HW_BREAKPOINT=y
CONFIG_HAVE_ARCH_TRACEHOOK=y

# kernel module
CONFIG_MODULES=y
CONFIG_MODULE_UNLOAD=y
CONFIG_MODVERSIONS=y

# eBPF
CONFIG_BPF=y
CONFIG_BPF_SYSCALL=y
CONFIG_BPF_JIT=y
CONFIG_HAVE_EBPF_JIT=y
CONFIG_UPROBES=y
CONFIG_UPROBE_EVENTS=y
CONFIG_NET_CLS_BPF=y
CONFIG_NET_ACT_BPF=y
CONFIG_FTRACE=y
# CONFIG_FTRACE_SYSCALLS=y
EOF

commit 修改
#

这里需要 commit 一下, 因为我们新增了文件, 直接编译的话会在内核版本后追加一个 -dirty

这里只需要本地 cmooit, 不必 push, 这样改动了后面也好处理

cd private/gs-google
git add .
git commit -m "> Add: shark.fragment"

开始编译
#

指定编译配置和 fragment，正式开跑：

BUILD_CONFIG=private/gs-google/build.config.gki.aarch64 \
GKI_DEFCONFIG_FRAGMENT=private/gs-google/arch/arm64/configs/shark.fragment \
LTO=thin build/build.sh -j32 2>&1 | tee build.log

0x8 后记
#

这一趟走下来，最大的教训就是：Mac 上搞内核编译，先建区分大小写的磁盘映像，不能头铁。

踩坑顺序大致是：

  1. 直接 Mac 本机编译 ← 没有合适的 arm64 交叉编译器，失败
  2. VMWare arm64 Ubuntu ← 还是没有合适的交叉编译器，失败
  3. Docker amd64 Ubuntu + 手动 git clone ← 编译过了，但刷进去开不了机
  4. Docker amd64 Ubuntu + Repo 下载源码 ← 各种诡异编译报错
  5. 区分大小写磁盘映像 + Docker + Repo ← 终于找到正解

也是折腾了好一阵才理清，不过搞明白之后回头看，逻辑其实很清楚：内核源码就是给 Linux（区分大小写的文件系统）写的，凑合在 Mac 默认文件系统上跑必然各种水土不服。
